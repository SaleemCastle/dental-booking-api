# P4 Insurance v1 acceptance QA

## Scope and result

This review covers the merged P4 insurance domain through M6 and the M7 acceptance criteria. Targeted local PostgreSQL application tests and API contract checks pass; this is not production or hosted release evidence. PR #73 fixed two runtime defects: the reporting controller lacked its service import, and the remittance advice model queried a singular table name while the migration creates the plural table. This pass also completed the missing M5 OpenAPI/Postman contracts and fixed migration-test teardown order and concurrency-fixture cleanup. **M7 remains incomplete pending hosted test evidence and the product scope decision below.**

Settlement v2 posting, allocation, refunds, reversals, and activation remain deferred. The nonposting eligibility, benefits, estimate, claim, authorization, appeal, remittance, receipt, and insurer-obligation workflows are within Insurance v1; deferred financial posting is not an Insurance v1 defect or blocker.

## Test and CI evidence

- Previously recorded focused unit/domain runs: 27 tests / 148 assertions; claim-response tests: 9 / 43 assertions; M6 access-policy tests: 4 / 8 assertions. These results are carried forward as prior evidence and were not rerun during this M7 pass.
- `InsuranceReportingApiTest`: **3 tests / 35 assertions passed** on a disposable local PostgreSQL 16 database after the two runtime fixes. The cases cover exact permission and wildcard denial, active tenant membership, tenant isolation, aggregate-only fields, audit, date validation, and cache headers.
- `PatientInsuranceApiTest`: **16 tests / 179 assertions passed** when run by itself on the same PostgreSQL test database. This confirms the patient API count failures in the curated combined run were caused by cross-file migration/test ordering, not by the isolated test file.
- The final curated P4 PostgreSQL run passed **126 tests / 1,545 assertions across 17 feature files**. It includes catalog, patient insurance, benefit, estimate, claim, eligibility, reporting, prior authorization, evidence, and OpenAPI/Postman contract checks. The reporting tests verify exact permissions, wildcard denial, tenant isolation, aggregate-only fields, audit, date validation, and cache headers. Migration compatibility tests now roll dependent migrations back in reverse order and restore them forward; claim concurrency tests remove committed fixtures from the disposable test database.
- Five focused OpenAPI/Postman contract tests passed **108 assertions**. `tests/Unit/PostmanExportTest.php` passed **12 tests / 680 assertions**, and `php tools/postman.php --check` passed. The contracts now cover all 40 `/api/insurance/*` routes, including remittance advice, receipts, and insurer obligations.
- The 17-file curated scope was: `PatientInsuranceIntegrationPostgresTest`, `InsuranceCatalogPostgresTest`, `InsuranceBenefitRulesPostgresTest`, `InsuranceCatalogContractTest`, `InsuranceObservationContractTest`, `InsuranceCatalogApiTest`, `InsuranceBenefitRulesTest`, `InsuranceBenefitContractTest`, `InsuranceEstimatePostgresTest`, `PatientInsuranceContractTest`, `InsuranceClaimPostgresTest`, `ManualInsuranceEligibilityTest`, `PatientInsuranceApiTest`, `InsuranceReportingApiTest`, `InsurancePriorAuthorizationPostgresTest`, `InsuranceEvidenceApiTest`, and `InsuranceEvidenceContractTest`.
- Tests ran with the repository's locked Composer dependencies and PHP 8.2 `pdo_pgsql` extension, using an isolated local PostgreSQL 16 test database. No production database or live insurer service was used.
- GitHub PR #70 was merged at `55d6b48`. Its `tests.yml` workflow run [45253685640](https://github.com/SaleemCastle/dental-booking-api/actions/runs/45253685640) concluded failure with zero jobs. The successful `pull_request_target` run was a metadata workflow, not application testing. Therefore there is no green hosted PostgreSQL test evidence for M6/M7.
